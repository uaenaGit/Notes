> 🔗[209 - 长度最小的子数组](https://leetcode.cn/problems/minimum-size-subarray-sum/description/?envType=study-plan-v2&envId=top-interview-150)

## 📌 题目描述
> （请在此处粘贴题目描述）

给定一个含有 `n` 个正整数的数组和一个正整数 `target` **。**

找出该数组中满足其总和大于等于 `target` 的长度最小的 **子数组** `[numsl, numsl+1, ..., numsr-1, numsr]` ，并返回其长度。**如果不存在符合条件的子数组，返回 `0` 。

**示例 1：**

**输入：** target = 7, nums = [2,3,1,2,4,3]
**输出：** 2
**解释：** 子数组 `[4,3]` 是该条件下的长度最小的子数组。

**示例 2：**

**输入：** target = 4, nums = [1,4,4]
**输出：** 1

**示例 3：**

**输入：** target = 11, nums = [1,1,1,1,1,1,1,1]
**输出：** 0

**提示：**

- $1 <= target <= 10^9$
- $1 <= nums.length <= 10^5$
- $1 <= nums[i] <= 10^4$

## 💡 解题思路 
使用滑动窗口。枚举右端点`right`， 不断更新左端点 `left`。

## 💻 代码实现
> my answer
```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int n = nums.size(), s = 0, left = 0;
        int ans = n + 1;
        for (int right = 0; right < n; right++) {
            s += nums[right];
            while (s >= target) {
                ans = min(ans, right - left + 1); // 更新窗口
                s -= nums[left];
                left++;
            }
        }
        return ans <= n ? ans : 0;
    }
};
```

- **时间复杂度**：`O(n)`
这段代码使用的是经典的**滑动窗口（双指针）** 算法。虽然代码中有两层循环（一个 `for` 循环嵌套一个 `while` 循环），看起来像是 $O(n^2)$，但实际上它的时间复杂度是 **$O(n)$**。

 **核心原因：每个元素最多被访问两次**

判断时间复杂度的关键不是看“有几层循环”，而是看**代码中的核心操作总共执行了多少次**。

在这个算法中，核心操作只有两个：
1.  **右指针 `right` 向右移动**（扩大窗口）：由外层 `for` 循环控制。
2.  **左指针 `left` 向右移动**（缩小窗口）：由内层 `while` 循环控制。

**详细推导过程：**

1.  **`right` 指针的运动**：
    *   `right` 从 `0` 开始，一直增加到 `n-1`。
    *   在这个过程中，`right` **只增不减**。
    *   `s += nums[right]` 这行代码总共执行了 **$n$ 次**。

2.  **`left` 指针的运动**：
    *   `left` 初始为 `0`。
    *   只有当 `s >= target` 时，`left` 才会执行 `left++`。
    *   关键点：**`left` 永远不可能超过 `right`**（最极端的情况是窗口缩小到空，此时 `left = right + 1`，循环就会停止）。
    *   因此，`left` 从 `0` 开始，最多也只能增加到 `n`。
    *   `s -= nums[left]` 和 `left++` 这些操作在整个程序运行过程中，总共执行的次数**不会超过 $n$ 次**。

3.  **总操作次数**：
    *   每个元素 `nums[i]` 最多被 `right` 加进窗口一次。
    *   每个元素 `nums[i]` 最多被 `left` 移出窗口一次。
    *   总操作次数 $\approx n (\text{right移动}) + n (\text{left移动}) = 2n$。

根据大 $O$ 表示法，忽略常数系数，$O(2n) = O(n)$。

 **🧠 形象理解**

你可以把 `left` 和 `right` 想象成一条虫子在爬行：
*   `right` 是虫子的头，`left` 是虫子的尾巴。
*   虫子从头到尾爬过数组一次（`right` 走 $n$ 步）。
*   在这个过程中，尾巴（`left`）为了保持身体收缩，也会跟着向前走，但尾巴**绝对不会倒退**，也**绝对不会超过头**。
*   所以，头和尾巴加起来走过的总路程最多是数组长度的 2 倍。

**❌ 为什么不是 $O(n^2)$？**

如果是 $O(n^2)$，意味着对于每一个 `right` 的位置，`left` 都要从 `0` 重新遍历到 `right`。
但在本代码中：
*   当 `right` 移动到下一个位置时，`left` **接着上一次停止的位置继续移动**，而不是重置回 `0`。
*   这种“不回退”的特性保证了线性时间复杂度。

**总结**

| 指针 | 移动方向 | 最大移动次数 | 对应操作 |
| :--- | :--- | :--- | :--- |
| `right` | 单向向右 | $n$ | `s += nums[right]` |
| `left` | 单向向右 | $\le n$ | `s -= nums[left]`, `left++` |
| **总计** | - | **$\le 2n$** | **$O(n)$** |

这就是滑动窗口算法的精髓：**用两个同向移动的指针，将原本需要双重循环的问题优化为单次遍历。**

- **空间复杂度**：`O(1)`
