考研上机考试往往时间紧张，题目数量多，且难度不一。

很多同学在面对一道题时，第一反应可能是“我不会最优解法”“这个算法太复杂了，写不完”。但请记住，考试的目标不是追求理论上的最优解，而是**在有限时间内拿到最多的分数**。通常，机试按通过测试点的数量给分，一道题即使没有完全正确，也能获得部分分数。

那么，如何在不完全掌握最优解法的情况下尽可能得分？答案就是：**使用“不合适”的算法**。这些算法在理论上可能效率低下（如暴力枚举、朴素搜索、错误的贪心），但在实际考试中，由于测试数据可能较弱或存在小数据部分，它们往往能通过一部分甚至全部测试点，从而让你拿到可观的分数。

本文将从实际应试角度出发，系统介绍各类“不合适”算法的适用场景、实现技巧和注意事项，帮助你在考场上灵活应变，最大化得分。

## 为什么“不合适”的算法能得分？

1. **多档数据范围**：很多题目会设置多组测试数据，其中包含小规模数据。例如，题目描述中可能给出“对于 30% 的数据，n ≤ 20；对于 100% 的数据，n ≤ 10^5”。如果你的暴力算法只能处理 n ≤ 20 的情况，那么至少能拿到 30% 的分数。
2. **测试数据较弱**：有时出题人为了降低难度，实际测试数据并不像理论极限那么极端。例如，理论上需要 O(n log n) 的排序题，如果直接用 O(n²) 的冒泡排序，在随机小数据下也能通过。
3. **剪枝优化效果好**：很多暴力算法加上简单的剪枝后，在随机数据下运行飞快，甚至能通过所有测试点。
4. **样例得分**：某些考试中，样例测试点单独占分，直接**输出样例答案**就能白拿一部分分数。

因此，学会判断何时可以用“不合适”算法，以及如何快速实现它们，是考研上机的重要技能。

## 常见的“不合适”算法及其应用场景

### 1. 暴力枚举

**适用场景**：

- 数据范围极小，例如 n ≤ 20，可以直接枚举所有子集（2^n）、全排列（n!）或组合。
- 问题规模小，但循环层数少，例如双重循环能处理 10^4 级别的数据。
- 可剪枝的枚举，如求满足条件的组合，一旦超出限制就停止。

**技巧**：

- 用位运算枚举子集：`for (int mask = 0; mask < (1 << n); mask++)`。
- 用 `next_permutation` 枚举全排列。
- 对于求和、求积类问题，直接两层循环。

**示例**：  
题目：给定 n 个整数，求有多少个子集的和等于 target。  
若 n ≤ 20，可以直接枚举所有子集：

```cpp
int n, target, a[25];
cin >> n >> target;
for (int i = 0; i < n; i++) cin >> a[i];
int ans = 0;
for (int mask = 0; mask < (1 << n); mask++) {
    int sum = 0;
    for (int i = 0; i < n; i++) {
        if (mask >> i & 1) sum += a[i];
    }
    if (sum == target) ans++;
}
cout << ans << endl;
```

运算量：2^n * n，当 n=20 时约为 2e7，C++ 1秒内可完成。

### 2. 朴素搜索（DFS/BFS）

**适用场景**：

- 状态空间较小，如迷宫大小 ≤ 10×10，八皇后问题（n≤10）。
- 虽然理论状态很多，但实际搜索树深度有限，且可加简单剪枝。

**技巧**：

- 使用递归实现 DFS，注意标记访问，避免重复。
- BFS 适合求最短路径，用队列实现。
- 可行性剪枝：当前路径已经不满足条件时，立即返回。
- 最优性剪枝：当前代价已经大于已知最优解，剪掉。

**示例**：  
题目：迷宫从起点到终点的最短步数，迷宫大小 ≤ 15×15。  
直接用 BFS 即可，无需 A* 或双向 BFS：

```cpp
int n, m, sx, sy, ex, ey;
char maze[20][20];
int dist[20][20];
int dx[4] = {1, -1, 0, 0};
int dy[4] = {0, 0, 1, -1};

int bfs() {
    memset(dist, -1, sizeof(dist));
    queue<pair<int, int>> q;
    q.push({sx, sy});
    dist[sx][sy] = 0;
    while (!q.empty()) {
        auto [x, y] = q.front(); q.pop();
        if (x == ex && y == ey) return dist[x][y];
        for (int i = 0; i < 4; i++) {
            int nx = x + dx[i], ny = y + dy[i];
            if (nx >= 0 && nx < n && ny >= 0 && ny < m && maze[nx][ny] != '#' && dist[nx][ny] == -1) {
                dist[nx][ny] = dist[x][y] + 1;
                q.push({nx, ny});
            }
        }
    }
    return -1;
}
```

状态数最多 225 个，BFS 极快。

### 3. 错误的贪心策略

**适用场景**：

- 有些问题的最优解法是贪心，但考生记不清正确策略，采用了一个直觉上合理但实际可能错误的贪心。
- 例如背包问题按价值/重量贪心（分数背包正确，0-1背包错误），但在某些测试数据下恰好正确。
- 活动安排按结束时间贪心（正确），但如果记反了按开始时间贪心，则可能错。

**示例**：  
题目：0-1 背包，n≤1000，容量≤1000。  
正确解法是 DP。若不会，可以尝试按价值/重量降序贪心选取：

```cpp
struct Item { int w, v; } items[1005];
sort(items, items + n, [](Item a, Item b) {
    return a.v * 1.0 / a.w > b.v * 1.0 / b.w;
});
int ans = 0, cap = C;
for (int i = 0; i < n; i++) {
    if (items[i].w <= cap) {
        ans += items[i].v;
        cap -= items[i].w;
    }
}
cout << ans << endl;
```

这个算法对于 0-1 背包是错的，但如果数据随机且物品重量分布均匀，可能得分不低。

### 4. 模拟代替高级数据结构

**适用场景**：

- 需要并查集但不会路径压缩，用数组加循环查找父节点（O(n) 查找），但数据小可接受。
- 需要链表但不想写指针，用数组模拟（pre 和 nxt 数组）。
- 需要线段树但不会，用数组加暴力更新查询（单次 O(n)）。

**示例**：  
题目：有 n 个元素，m 次合并操作和查询操作，n ≤ 1000，m ≤ 1000。  
可以用最朴素的并查集（不压缩）：

```cpp
int fa[1005];
int find(int x) {
    while (fa[x] != x) x = fa[x];
    return x;
}
void unite(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) fa[fx] = fy;
}
```

每次查找最坏 O(n)，总复杂度 O(nm) = 1e6，完全可以接受。

### 5. 浮点数处理代替高精度

**适用场景**：

- 需要计算大数的阶乘、组合数，但数值范围在 double 的精度内（约 1e308，有效数字 15 位）。
- 结果要求浮点数或近似值，不需要精确整数。

**示例**：  
题目：求组合数 C(n, m)，n ≤ 100。  
直接用 double 累乘累除：

```cpp
double C(int n, int m) {
    if (m > n - m) m = n - m;
    double res = 1.0;
    for (int i = 1; i <= m; i++) {
        res = res * (n - m + i) / i;
    }
    return res;
}
```

n=100 时结果约 1e29，double 能表示，但可能丢失个位数，不过对于部分测试点（如输出浮点数）足够了。

### 6. 针对特殊性质的暴力

**适用场景**：

- 素数判断：用试除法 O(sqrt(n))，当 n ≤ 10^6 时，单次判断很快。
- 求最大公约数：直接用辗转相除法（本身高效）。
- 字符串匹配：用朴素 `O(n*m)` 算法，当长度 ≤ 1000 时可行。

**示例**：  
题目：判断 10^5 个数是否为素数，每个数 ≤ 10^6。  
用试除法，总运算量约 10^5 * sqrt(10^6) ≈ 3e8，可能稍大，但可优化：只判断奇数，且当遇到因子时提前退出。实际随机数据下平均运算量远小于此，可能通过。

### 7. NP-hard 问题的状态压缩枚举

**适用场景**：

- 旅行商问题（TSP）、图着色等 NP-hard 问题，n ≤ 15 时可用状压 DP 或全排列枚举。
- 全排列枚举：n!，当 n ≤ 10 时约 3.6e6，可行。

**示例**：  
题目：给定 n 个点，求最短哈密顿路径，n ≤ 10。  
枚举所有排列：

```cpp
int n, dist[15][15];
int a[15];
for (int i = 0; i < n; i++) a[i] = i;
int ans = INF;
do {
    int sum = 0;
    for (int i = 0; i < n-1; i++) sum += dist[a[i]][a[i+1]];
    ans = min(ans, sum);
} while (next_permutation(a, a + n));
cout << ans << endl;
```

10! = 3.6e6，内层循环 O(n)，总运算约 3.6e7，C++ 可过。

### 8. 输出样例

**适用场景**：

- 完全不会做，时间所剩无几。
- 题目样例**有明确输出**，且样例测试点单独占分。

**示例**：  
直接写：

```cpp
int main() {
    cout << "样例输出" << endl;
    return 0;
}
```

至少得样例分。

### 9. 知道近似算法或者小范围正解算法

**适用场景**：

- 完全不会做，但是知道有别的方法可以求正解或者近似解。
- 题目样例有明确输出，且样例测试点单独占分。

**示例**：  
求最短路的题，节点个数很多，忘了堆优化的Dijkstra，那么就用BFS/Floyd甚至随机求最短路来解决。虽然有Case会超时，但是如果数据分布不均匀，也有可能拿到很高的分数。

## 如何评估能否用“不合适”算法？

在考场上快速判断能否暴力，需要估算时间复杂度和空间复杂度。

### 时间估算

- C++ 1 秒大约可执行 10^8 次简单运算（加减乘除、比较）。保守估计，10^7 以内绝对安全，10^8 可能勉强，10^9 几乎必超时。
- 注意循环内如果有函数调用或复杂操作，要适当打折。
- 多组测试数据时，总运算量 = 单组运算量 × 组数，需控制在 10^7 ~ 10^8。

### 空间估算

- 数组大小：int 数组 10^6 约 4MB，10^7 约 40MB，注意内存限制（通常 256MB 或 512MB）。
- 递归深度：DFS 递归深度过大会栈溢出，可改用栈模拟或 BFS。

### 数据范围分析

- 题目描述中常给出不同数据范围的子任务，如“对于 30% 的数据，n ≤ 20”。直接针对小数据写暴力，至少拿 30%。
- 若题目未明确分档，可观察 n 的最大值。若 n ≤ 1000，O(n²) 通常可行（1e6 运算）；若 n ≤ 100，O(n³) 也可行（1e6）。

### 剪枝优化

- 搜索题：可行性剪枝、最优性剪枝、重复状态去重。
- 枚举题：利用对称性、排除不可能情况。
- 排序预处理：有时先排序可减少枚举量。

## 实战技巧

1. **先看数据范围**：拿到题目后，第一件事是看输入限制。如果 n ≤ 20，直接暴力；如果 n ≤ 1000，考虑 O(n²) 算法。
2. **估算最坏情况**：假设最坏数据，计算循环次数。若超过 10^8，考虑剪枝或换思路。
3. **利用“部分分”**：即使不能全过，也要针对小数据写暴力，确保拿到基础分。
4. **剪枝优化**：在暴力中加入简单的判断，如提前退出、排序后剪枝，往往能大幅提升效率。
5. **多组数据处理**：如果有多组测试数据，注意重置变量，避免上次结果影响。
6. **对拍调试**：平时练习时，可以用暴力程序与正确程序对拍，验证暴力的正确性。
7. **心态**：不要因为不会最优解而放弃，**暴力也是一种能力**。在考场上，暴力往往比空着强。

## 心态调整

考研上机考试不仅是算法的比拼，更是策略和心态的较量。遇到难题时，保持冷静，问自己：

- 我能否用**暴力**拿到部分分？
- 有没有更简单的思路？
- 时间还够不够写一个能过样例的程序？

记住：**能拿一分是一分**。有时候，一道看似复杂的题，暴力就能过，而你想太多反而浪费时间。平时练习时，也要刻意训练快速实现暴力的能力，确保在考场上能熟练写出枚举、搜索等基础代码。
