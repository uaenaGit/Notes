## 1. 先确定运行策略

## 3. 建议预留的磁盘空间

- HW3/HW4 最小本地环境：约 2-5GB。
- HW9 本地 Whisper 环境及模型：约 3-10GB，取决于模型大小。
- 仓库完整环境：可能超过 20GB。
- 7B 模型、Stable Diffusion、训练检查点与缓存：可能额外占用几十 GB。

不建议把大型模型缓存放在系统盘。可以在 PowerShell 中临时指定缓存目录：

```powershell
New-Item -ItemType Directory -Force 'D:\AI-Cache\huggingface' | Out-Null
New-Item -ItemType Directory -Force 'D:\AI-Cache\torch' | Out-Null

$env:HF_HOME = 'D:\AI-Cache\huggingface'
$env:TORCH_HOME = 'D:\AI-Cache\torch'
```

以上设置只对当前 PowerShell 窗口有效。若希望永久设置：

```powershell
[Environment]::SetEnvironmentVariable('HF_HOME', 'D:\AI-Cache\huggingface', 'User')
[Environment]::SetEnvironmentVariable('TORCH_HOME', 'D:\AI-Cache\torch', 'User')
```

设置后重新打开 PowerShell。

## 5. 安装 uv


```powershell

```

```powershell
$env:Path += ";$env:USERPROFILE\.local\bin"
uv --version
```

也可以通过 Python 安装：

```powershell
python -m pip install --user uv
```

安装后若命令仍不可见，重新打开终端。

## 7. 为什么暂时不要执行完整的 uv sync

仓库 README 推荐：

```powershell
uv sync
```

但这个命令会尝试安装整个项目的所有依赖，包括：

- PyTorch、Transformers、Accelerate；
- bitsandbytes、PEFT、TRL；
- Diffusers；
- GPTQModel；
- llama-cpp-python；
- Inseq、Whisper、LangChain 等。

在 Windows、GTX 1050 Ti 和 4GB 显存的组合下，完整同步可能遇到：

- CUDA 或驱动版本不匹配；
- bitsandbytes Windows 支持问题；
- `llama-cpp-python` 本地编译失败；
- `gptqmodel` 构建失败；
- 下载时间很长；
- 安装成功但模型仍因显存不足无法运行。

完成 HW3/HW4 不需要这些重型依赖。只有在确实需要研究仓库其余本地功能时，才尝试：

```powershell
uv sync
```

项目注释说明 `gptqmodel` 首次构建失败时可以在 PyTorch 已落地后重试一次，但 Windows 上仍不保证完整同步成功。

## 8. 配置阿里云百炼 API Key

中文 Notebook 默认使用 OpenAI 兼容 SDK 调用阿里云百炼，常见配置是：

```python
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
model = "qwen-plus"
```

在阿里云百炼控制台创建 API Key 后，在启动 Jupyter 的同一个 PowerShell 窗口中设置：

```powershell
$env:OPENAI_API_KEY = '替换为你自己的百炼APIKey'
```

然后启动 Jupyter：

```powershell
.\.venv\Scripts\python.exe -m jupyter lab
```

可以在 Notebook 中检查环境变量是否存在，但不要打印完整密钥：

```python
import os

api_key = os.getenv("OPENAI_API_KEY")
print("API Key 已配置" if api_key else "API Key 未配置")
```

创建客户端：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)
```

最小连通性测试：

```python
response = client.chat.completions.create(
    model="qwen-plus",
    messages=[{"role": "user", "content": "只回复：API 测试成功"}],
)
print(response.choices[0].message.content)
```

安全注意事项：

- 不要把真实密钥直接写进 Notebook；
- 不要提交包含密钥的截图；
- 不要把密钥提交到 Git；
- 不要在公开 Kaggle Notebook 中写入密钥；
- API Key 泄露后应立即在服务商控制台撤销并重新生成。

`$env:OPENAI_API_KEY` 只对当前 PowerShell 进程及其启动的 Jupyter 有效，关闭窗口后自动失效，这比把密钥永久写入系统环境变量更安全。

## 12. 在 Kaggle 中安全配置密钥

在 Kaggle Notebook 页面打开 `Add-ons` 或 `Secrets`，添加：

- 名称：`OPENAI_API_KEY`
- 值：你的阿里云百炼 API Key

Notebook 中读取：

```python
import os
from kaggle_secrets import UserSecretsClient

secrets = UserSecretsClient()
os.environ["OPENAI_API_KEY"] = secrets.get_secret("OPENAI_API_KEY")
```

如果需要 Hugging Face Token，再添加：

- 名称：`HF_TOKEN`
- 值：Hugging Face Access Token

读取并登录：

```python
import os
from kaggle_secrets import UserSecretsClient
from huggingface_hub import login

secrets = UserSecretsClient()
os.environ["HF_TOKEN"] = secrets.get_secret("HF_TOKEN")
login(token=os.environ["HF_TOKEN"])
```

Kaggle Secret 应保持为私有。不要在输出中 `print()` Secret。

## 22. 常见错误处理

### 22.1 uv 不是内部或外部命令

重新打开 PowerShell，或执行：

```powershell
$env:Path += ";$env:USERPROFILE\.local\bin"
uv --version
```

### 22.2 Jupyter 使用了错误的 Python

在 Notebook 中运行：

```python
import sys
print(sys.executable)
```

HW3/HW4 应指向：

```text
...\LLM-Guide-and-Demos-zh_CN\.venv\Scripts\python.exe
```

HW9 应指向：

```text
...\LLM-Guide-and-Demos-zh_CN\.venv-hw9\Scripts\python.exe
```

如果不是，重新选择正确的 Jupyter 内核。

### 22.3 API 返回 401

检查：

- API Key 是否为空；
- Key 是否复制完整；
- Key 是否属于当前 `base_url` 对应的平台；
- Jupyter 是否从配置环境变量的 PowerShell 窗口启动；
- Key 是否已在控制台撤销。

### 22.4 API 返回 429

通常表示：

- 账户余额或免费额度不足；
- 请求频率过高；
- 同时运行了多个调用单元格。

降低并发、等待后重试，并检查服务商控制台的余额和限流规则。

### 22.5 CUDA out of memory

依次处理：

1. 停止当前单元格。
2. 重启 Notebook 内核或云端运行时。
3. 将 batch size 降为 1。
4. 缩短输入长度或降低图片分辨率。
5. 使用梯度累积。
6. 使用 FP16/BF16 或量化模型。
7. 不要同时加载多个模型。

对于 GTX 1050 Ti，HW5、HW6、HW8、HW10 出现 OOM 是硬件限制，不应把大量时间花在本地调参上。

### 22.6 模型无法下载

检查：

- Kaggle/Colab 是否打开 Internet；
- Hugging Face 模型是否需要申请访问；
- `HF_TOKEN` 是否已设置；
- 模型名称是否仍然存在；
- 磁盘空间是否足够；
- 下载是否被网络中断。

不要在下载到一半时反复执行相同单元格，否则可能留下多个不完整缓存。必要时重启环境后再下载。

### 22.7 bitsandbytes、GPTQ 或 llama-cpp-python 安装失败

这些依赖在 Windows 上容易受 CUDA、编译器和 Python 版本影响。完成课程 HW3/HW4 时不需要它们。训练作业应使用仓库提供的 Kaggle/Colab 环境。

### 22.8 Gradio 页面无法显示

先查看单元格输出是否出现 `127.0.0.1` 或共享 URL。复制该地址到浏览器。如果端口占用，重启 Notebook 内核后重新运行 Gradio 单元格。

### 22.9 中文路径引发原生工具错误

多数 Python 包能够处理当前中文路径，但部分旧版编译工具、FFmpeg 脚本或模型工具可能失败。如果错误明确指向路径编码，可把仓库复制到纯英文路径，例如：

```text
D:\AI\LLM-Guide-and-Demos-zh_CN
```

只有出现路径相关错误时才需要这样处理。
