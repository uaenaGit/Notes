# 大模型学习路线：跨专业研一到就业

> [!abstract] 我的目标
> 背景：浙大计算机研一，本科材料，工作一年多后跨考；用过 C、Git 和常用 Linux 命令，学习过 Python 入门书，接触过李宏毅生成式 AI 导论。
>
> 三年目标：能够独立完成有数据、有评测、有实验、有工程实现的大模型项目；在一个细分方向上积累科研或实习经验，并具备计算机岗位的基础面试能力。

> [!note] 使用方式与时间假设
> 以每周 **15～20 小时的方向学习时间**设计，时间包含课程、代码、实验和复盘；学校课程、组内任务另行协调。阶段时长是参考，不是硬性截止日期。以验收标准决定是否进入下一阶段。
>
> 主线：**基础 → PyTorch → Transformer 与小型 GPT → CS336 → 细分方向项目 → 科研与实习 → 求职**。
>
> 不需要把这里的所有资料都学完。每阶段先完成“主线”，遇到问题再查“选读”。课程网页可能随年份调整；下面的链接是资源入口或明确年份的公开版本，不表示它们是最新版本。

## 一、先确定投入方向

| 方向 | 典型工作 | 重点能力 | 适合我的探索方式 |
| --- | --- | --- | --- |
| 后训练与模型算法 | 数据构建、SFT、偏好优化、领域适配、评测 | 深度学习、实验设计、数据分析 | 先做小模型微调与可靠评测，再深入一个问题 |
| 系统与推理优化 | 推理服务、显存与性能优化、算子、分布式 | C/C++、OS、体系结构、CUDA、性能分析 | 用已有 C/Linux 经验切入，补计算机系统基础 |
| 应用算法与工程 | RAG、工具调用、检索、业务评测与部署 | Python 工程、检索、后端、数据处理 | 尽早做完整项目，但要加入评测和错误分析 |
| 预训练研究 | 数据配比、结构、训练策略、规模规律 | 理论、研究方法、算力与团队支持 | 通过 CS336 建立理解，再结合课题组资源选择 |

**初步选择：** 前半年学习共同基础；研一后半段重点比较“后训练”和“系统优化”。最终选择需结合导师方向、个人兴趣、算力与数据条件。

材料背景可以用于材料文献抽取、领域检索和专业问答，但是否选这个领域，要看能否获得可靠数据和专业评测支持。

## 二、阶段 1：Python、数学与机器学习基础

**建议时间：第 1～3 个月。目标：独立完成一个简单模型的训练、验证与保存。**

### 主线资料与学习范围

| 资料 | 链接 | 学习范围与用法 |
| --- | --- | --- |
| 《动手学深度学习》PyTorch 版 | https://zh.d2l.ai/ | 先学预备知识、线性神经网络、多层感知机；边看边运行代码 |
| PyTorch Learn the Basics | https://pytorch.org/tutorials/beginner/basics/intro.html | Tensor、Dataset/DataLoader、模型、自动求导、优化、保存与加载 |
| NumPy 官方入门 | https://numpy.org/doc/stable/user/absolute_beginners.html | 数组、索引、形状、广播、矩阵运算 |
| 3Blue1Brown 线性代数 | https://www.3blue1brown.com/topics/linear-algebra | 建立向量、线性变换、矩阵乘法的直觉；配合实际计算 |
| 3Blue1Brown 微积分 | https://www.3blue1brown.com/topics/calculus | 导数、链式法则的直觉；落实到梯度计算 |

**数学最低清单：**

- [ ] 线性代数：向量、矩阵、矩阵乘法、转置、内积、范数。
- [ ] 微积分：导数、偏导、链式法则、梯度。
- [ ] 概率统计：条件概率、期望、方差、常见分布、最大似然。
- [ ] 机器学习：训练/验证/测试划分、损失函数、过拟合、正则化、数据泄漏。

**选读：** [CS229 课程资料](https://cs229.stanford.edu/)中的线性代数、概率和学习笔记；[StatQuest](https://www.youtube.com/@statquest)用于补具体概念。遇到不懂的知识再查，不要求此时完整学完 CS229。

### 推荐项目

**项目 1A：NumPy 线性回归。** 使用人工生成数据，实现预测、均方误差、梯度和参数更新；画出损失曲线，用有限差分抽查梯度是否正确。

**项目 1B：PyTorch 分类训练闭环。** 使用 Fashion-MNIST 或类似小数据集，实现 MLP 分类器，包含训练、验证、保存和恢复；比较两三个学习率，记录训练与验证表现。

### 验收标准

- [ ] 不照着完整答案，能写出训练循环。
- [ ] 能解释 `zero_grad()`、`backward()`、`step()` 和 `train()/eval()`。
- [ ] 能解释 `eval()` 与 `no_grad()` 解决的问题有何不同。
- [ ] 能解释为什么不能用测试集调参。
- [ ] 能观察并说明学习率过大、过拟合等现象。
- [ ] 仓库中有依赖说明、运行命令和一份实验记录。

## 三、阶段 2：深度学习、Transformer 与小型 GPT

**建议时间：第 4～6 个月。目标：理解并训练一个小型自回归语言模型。**

### 主线资料与学习范围

| 资料 | 链接 | 学习范围与用法 |
| --- | --- | --- |
| 《动手学深度学习》 | https://zh.d2l.ai/ | 优化、序列模型基本思想、注意力与 Transformer；CNN/RNN 先掌握基本原理 |
| Karpathy：Neural Networks: Zero to Hero | https://karpathy.ai/zero-to-hero.html | 按 micrograd → makemore → GPT 的顺序推进，代码与讲解一起学 |
| The Illustrated Transformer | https://jalammar.github.io/illustrated-transformer/ | 用图建立结构直觉，之后回到代码确认维度 |
| Attention Is All You Need | https://arxiv.org/abs/1706.03762 | 第一篇精读论文；重点看注意力、多头、位置编码与结构 |

**选读：** [Stanford CS224N](https://web.stanford.edu/class/cs224n/)中与词向量、注意力、Transformer、语言模型有关的内容。原始 Transformer 论文是编码器—解码器结构，学习 GPT 时还要理解 decoder-only 和因果掩码。

### 推荐项目：从零实现小型 GPT

参考 [nanoGPT](https://github.com/karpathy/nanoGPT) 理解工程结构，然后自己实现关键模块。使用小型、许可清楚的文本数据；先从字符级建模开始，也可以后续替换 tokenizer。

必做内容：

- [ ] Token embedding、位置表示、causal self-attention、多头注意力。
- [ ] 前馈网络、残差连接、LayerNorm。
- [ ] Next-token prediction、交叉熵和自回归生成。
- [ ] 训练/验证文本分离；避免相同或高度重复内容跨集合泄漏。
- [ ] 损失曲线、采样文本、配置与 checkpoint。
- [ ] 在极小数据集上尝试过拟合，检查训练逻辑。

做 3 组有明确问题的小实验，例如比较学习率、上下文长度、模型层数。每组只改变少量因素，保留可比较的基线。

### 验收标准

- [ ] 能从输入 token 开始，写出每层的张量形状。
- [ ] 能解释因果掩码为什么必需，并用小例子验证其行为。
- [ ] 能说明训练时并行计算与生成时逐 token 解码的区别。
- [ ] 能解释 loss、困惑度、temperature 与 top-k 的基本含义。
- [ ] 能独立定位维度、设备、数据类型和 loss 异常问题。

## 四、阶段 3：CS336——把语言模型从原理推进到实现

**建议时间：第 7～11 个月，可与组内科研合并。目标：通过作业建立模型、训练与系统之间的完整认识。**

### 为什么现在再学

CS336 是斯坦福的 **Language Modeling from Scratch**。它适合成为主线工程训练，但要求一定的 PyTorch、数学、Transformer 和英文技术资料阅读基础。现在可先浏览课程结构，正式做作业放在前两个阶段之后。

### 资料与学习顺序

| 资料 | 链接 | 用法 |
| --- | --- | --- |
| CS336 Spring 2025 公开课程 | https://stanford-cs336.github.io/spring2025/ | 固定一个年份，按该版本讲义和作业配套学习 |
| Stanford CS336 GitHub 组织 | https://github.com/stanford-cs336 | 查对应作业仓库、说明与测试；具体要求以选定版本为准 |
| PyTorch 文档 | https://pytorch.org/docs/stable/index.html | 实现时查 API 和语义，避免凭印象使用 |

建议按课程所选版本安排顺序，重点打通：

1. **基础实现：** tokenizer、Transformer、优化器和训练循环。
2. **系统理解：** 性能分析、显存、混合精度、注意力实现及分布式基本概念。
3. **训练与数据：** 数据清洗、去重、数据质量、训练配置与验证。
4. **后续主题：** 根据课程版本和个人方向学习规模规律、对齐等内容。

每个作业先读要求、写最小实现、运行配套测试，再做实验。算力不足时可以降低模型规模或完成可运行的子实验；某些硬件/分布式实验无法等价缩小，需在报告中明确未验证范围。

### 推荐项目：小语言模型训练实验台

在阶段 2 项目基础上增加：配置文件、日志、断点恢复、tokenizer、数据处理、验证评测和性能统计。

产出一份报告，回答：

- 哪些设置影响验证损失？比较时控制了哪些变量？
- 性能瓶颈位于数据加载、模型计算还是其他部分？
- 模型大小、序列长度、batch size 怎样影响显存和吞吐量？
- 哪些结论只有在当前硬件与小规模实验下成立？

### 验收标准

- [ ] 完成所选核心作业并通过相应检查，记录完成与未完成部分。
- [ ] 能从原始文本解释到模型训练、评测与生成的全过程。
- [ ] 能读懂一个小型开源语言模型的主要实现。
- [ ] 有可复现的代码、配置和实验报告。

## 五、阶段 4：研二选择一条主线，深入做项目

**建议时间：第 12～20 个月。目标：做出一个能用于科研讨论和实习面试的代表作。以下 A/B 先选一个主攻。**

### A. 后训练与应用算法

**推荐资料：**

| 资料 | 链接 | 学习重点 |
| --- | --- | --- |
| Hugging Face LLM Course | https://huggingface.co/learn/llm-course/chapter1/1 | Transformers、Datasets、tokenizer、训练与模型使用 |
| Transformers 文档 | https://huggingface.co/docs/transformers/index | 模型加载、生成、训练接口 |
| PEFT 文档 | https://huggingface.co/docs/peft/index | LoRA 等参数高效微调方法与实现 |
| TRL 文档 | https://huggingface.co/docs/trl/index | 按项目需要学习 SFT 和偏好优化；核对版本与 API |
| LoRA 论文 | https://arxiv.org/abs/2106.09685 | 理解低秩适配的动机与方法 |
| DPO 论文 | https://arxiv.org/abs/2305.18290 | 在理解 SFT、偏好数据与基本 RLHF 思路后学习 |

**主项目：专业文献问答与领域适配对照实验。** 可选材料领域，也可选择能拿到可靠数据的其他领域。

按顺序完成：

1. 构建独立评测集，定义正确性、引用支持度、拒答与延迟等指标。
2. 建立基础模型直接回答、基础 RAG 两个基线。
3. 改进切块、检索和重排，分析召回失败与生成失败。
4. 有充分理由时增加 LoRA/SFT，比较“微调”“RAG”“二者结合”的效果。
5. 对错误分类，做消融实验，报告训练成本与推理成本。

**阶段产出：** 数据说明、评测协议、对照表、错误案例、可复现实验和演示。LLM-as-a-judge 可以辅助评测，但要有人抽查、统一评分规则并检查偏差。微调是否带来改进应由评测决定。

**扩展项目：** 针对同一类任务比较不同数据质量、数量或偏好构造方式。先把 SFT 与评测做好，再决定是否需要 DPO 或其他方法。

### B. 系统与推理优化

**推荐资料：**

| 资料 | 链接 | 学习重点 |
| --- | --- | --- |
| CSAPP | https://csapp.cs.cmu.edu/ | 内存、缓存、链接、并发等与性能相关的基础；按短板学习 |
| OSTEP | https://pages.cs.wisc.edu/~remzi/OSTEP/ | 进程、线程、虚拟内存、并发 |
| NVIDIA CUDA Programming Guide | https://docs.nvidia.com/cuda/cuda-programming-guide/ | GPU 执行模型、线程组织、内存、同步 |
| Triton Tutorials | https://triton-lang.org/main/getting-started/tutorials/index.html | 用简单算子进入 GPU kernel 编写与性能分析 |
| vLLM 文档与代码 | https://docs.vllm.ai/ | 推理服务、批处理、KV cache；挑一个模块深入 |
| FlashAttention 论文 | https://arxiv.org/abs/2205.14135 | 理解 IO 与注意力计算的关系 |
| PagedAttention 论文 | https://arxiv.org/abs/2309.06180 | 理解 KV cache 管理与推理服务效率 |

**准备项目：** 实现并验证一个简单 CUDA/Triton 算子，例如向量加法、softmax 或矩阵乘法的教学实现。比较数值误差和不同形状下的性能，不预设自己实现一定更快。

**主项目：小模型推理性能分析与优化。**

1. 固定硬件、模型、软件版本和基线。
2. 设计输入长度、输出长度、并发量组成的负载矩阵。
3. 记录首 token 延迟、后续 token 延迟、吞吐量与峰值显存；明确计时是否包含排队和预处理。
4. 使用 profiler 定位瓶颈，再选择 KV cache、批处理、量化或算子方向优化。
5. 检查数值/质量影响，重复测量，报告有效范围和退化场景。

**阶段产出：** benchmark 脚本、性能图、环境说明、正确性检查和优化报告。有合适问题时再尝试贡献开源 PR。

### 科研与英文阅读

## 十、资源与进度的取舍原则

- **算力不足：** 前期使用 CPU 或小模型即可推进；有 GPU 后再扩大实验。先确认组内资源，不急着购买硬件。CUDA、推理优化和部分 CS336 实验需相应 GPU 条件。
- **模型选择：** 优先用能在现有硬件运行、许可合适、文档清楚的小模型；根据实际显存和精度需求决定规模。
- **课程过载：** 同时最多保留一门主线课、一组补充材料和一个项目。
- **追热点：** 新方法先问它解决什么问题、与自己的项目有什么关系；每月复盘方向即可，不必每周切换技术栈。
- **使用 AI：** 可辅助解释、排错和代码审查；关键模块自己推导和验证，尤其是梯度、掩码、数据划分与评测。
- **就业目标：** 三年后的岗位需求存在变化。持续观察目标岗位，把编程、模型理解、评测、系统能力和领域经验转化为可展示的成果。
