# python -m venv .venv 
## 一、整条命令拆分释义
1. `python`：调用当前环境的Python解释器
2. `-m venv`：使用Python内置标准库 `venv`（虚拟环境工具，无需额外pip安装）
3. `.venv`：指定虚拟环境文件夹名称（`.`开头代表隐藏目录，行业通用命名）

## 二、核心作用
在**当前项目根目录**，创建一套**独立隔离的Python虚拟环境**：
1. 复制当前Python解释器副本到 `.venv` 文件夹；
2. 拥有独立的 `pip`，该项目安装的第三方包只会存放在 `.venv` 内部，不会污染全局Python；
3. 不同项目可以使用不同版本、不同集合的依赖包，解决包版本冲突。

## 三、执行后目录变化
执行命令后，当前文件夹会生成 `.venv` 文件夹，内部包含：
- `Scripts/`（Windows）：激活脚本 `activate.bat` / `Activate.ps1`
- `Lib/site-packages/`：存放本项目所有pip安装的库
- `pyvenv.cfg`：记录当前虚拟环境绑定的Python版本

## 四、Windows PowerShell 激活虚拟环境
### 1. PowerShell 执行激活
```powershell
.venv\Scripts\Activate.ps1
```
激活成功后，终端前缀会出现 `(.venv)` 标识，代表进入隔离环境。
### 常见报错解决
若提示**执行策略禁止运行脚本**，管理员PowerShell执行一次：
```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```
输入 `Y` 确认即可。

### 2. CMD 激活（备用）
```cmd
.venv\Scripts\activate.bat
```

## 五、基础使用流程完整示例
```powershell
# 1. 进入项目文件夹
cd D:\work\my_python_project
# 2. 创建虚拟环境
python -m venv .venv
# 3. 激活环境
.venv\Scripts\Activate.ps1
# 4. 安装项目依赖（仅作用于当前.venv）
pip install requests pandas
# 5. 导出依赖清单给别人复用
pip freeze > requirements.txt
# 6. 退出虚拟环境
deactivate
```

## 六、补充要点
1. `.venv` 文件夹体积较大，提交代码时务必加入 `.gitignore`，不要上传到仓库；
2. 虚拟环境仅本地使用，换电脑只需重新执行这条命令新建环境，再 `pip install -r requirements.txt` 恢复依赖；
3. VSCode识别：创建后左下角会自动提示选择 `.venv` 里的Python解释器，选中后调试、运行代码自动使用隔离环境。

# $env:PIP_CONFIG_FILE = (Resolve-Path .\pip.conf).Path（PowerShell语法）
## 完整命令
```powershell
$env:PIP_CONFIG_FILE = (Resolve-Path .\pip.conf).Path
```
## 1. 拆分每一部分作用
### ① `Resolve-Path .\pip.conf`
- `Resolve-Path`：PowerShell内置命令，**把相对路径转为绝对完整物理路径**，同时校验文件是否真实存在；
- `.\pip.conf`：当前项目根目录下的 `pip.conf` 文件（pip私有源配置文件）；
- 执行后返回路径对象，示例输出：`D:\Work\projects\ontology-builder\pip.conf`

### ② `.Path`
取上面路径对象的**纯文本绝对路径字符串**，去掉多余对象信息，只留下文件完整路径。

### ③ `$env:PIP_CONFIG_FILE`
`$env:` 代表**系统环境变量**，`PIP_CONFIG_FILE` 是pip官方识别的环境变量：
pip会读取这个变量指向的配置文件，用来替换默认pip源、配置私有仓库、超时、缓存等。

### ④ **=** 赋值
把前面拿到的 `pip.conf` 完整路径，赋值给环境变量 `PIP_CONFIG_FILE`。

## 2. 整条命令整体功能
临时设置环境变量，让当前PowerShell会话里所有`pip`命令**强制读取项目本地的pip.conf配置**，而不使用用户全局pip配置。

## 3. 和README里的命令对应
README里Windows PowerShell安装命令：
```powershell
$env:PIP_CONFIG_FILE = ".\pip.conf"; pip install -e .[dev]
```
简化写法和你这条命令效果一致，区别：
- 简化写法直接填相对路径；
- 你这条用`Resolve-Path`转为绝对路径，兼容性更好，避免路径解析出错。

## 4. 使用场景
项目内私有pip源、内部依赖包仓库，不想修改电脑全局pip配置，仅在当前项目终端生效，关闭终端后该环境变量自动失效。

## 5. 配套完整操作流程（你当前项目）
1. 先激活虚拟环境
```powershell
.\.venv\Scripts\Activate.ps1
```
2. 执行这条环境变量命令
```powershell
$env:PIP_CONFIG_FILE = (Resolve-Path .\pip.conf).Path
```
3. 执行安装
```powershell
pip install -e .[dev]
```

# python -c "import mbse_harness, pydantic, pypdf; print('Python dependencies OK')"
## 1. 命令拆分
```powershell
python -c "import mbse_harness, pydantic, pypdf; print('Python dependencies OK')"
```
- `python -c`：直接在终端执行一段单行Python代码，不用新建`.py`文件
- `import mbse_harness, pydantic, pypdf`：导入三个项目核心依赖包
  1. `mbse_harness`：你们项目内部的模型/本体工具库
  2. `pydantic`：数据模型校验库（项目里`BuildResult`这类类都依赖它）
  3. `pypdf`：PDF读取解析工具
- `;`：Python里分隔多条语句
- `print('Python dependencies OK')`：全部导入无报错就打印成功提示

## 2. 整体作用
**校验项目关键依赖是否完整安装成功**
- 执行不报错、输出 `Python dependencies OK` → 说明虚拟环境里三个包都装好，环境正常，可以运行项目代码；
- 如果报错 `ModuleNotFoundError` → 说明依赖没装全，需要重新跑 `pip install -e ".[dev]"`。

## 3. 使用时机
跑完 `pip install -e ".[dev]"` 之后执行这条，用来验证安装结果。


# python -m py_compile ` ".\src\ontology_builder_agent\extractor.py"
## 1. 整体作用
对 `extractor.py` 源码文件**预编译**，生成Python字节码文件（`.pyc`）。

## 2. 拆分每一段
### `python`
调用当前虚拟环境里的python解释器（你现在在`.venv`环境，用的是虚拟环境内Python）。

### `-m py_compile`
- `-m`：让Python**以模块方式运行**
- `py_compile` 是Python内置标准模块，不用额外`pip install`
功能：把 `.py` 源代码编译成 **pyc字节码文件**。

### `".\src\ontology_builder_agent\extractor.py"`
输入参数：你要编译的目标Python源码文件路径。

## 3. 执行之后会发生什么
运行这条命令，Python会：
1. 读取 `extractor.py`
2. 语法检查（如果代码有语法错误，这里直接报错）
3. 生成字节码文件
默认存放位置：
- Python3.2+ 会自动创建 `__pycache__` 文件夹
- 在里面生成类似 `extractor.cpython-311.pyc` 这种文件

> `.pyc` = 编译后的字节码。
> Python并不是直接运行源码，解释器会先把源码翻译成字节码；pyc就是缓存好的字节码，下次启动更快。

## 4. 重点澄清初学者常见误区
1. **不是C语言编译！**
`py_compile` **不能把Python转成exe、不能转C代码**，仅仅生成字节码。
依然需要Python解释器才能运行。

2. 能不能直接分发pyc给别人运行？
可以，但有局限：
- pyc版本和你的Python小版本强绑定；
- 一定程度上防源码直接查看，但**很容易反编译**，不能当做加密手段。

## 5. 和你项目的关联
这条命令典型用途：
1. **静态语法预检**：不运行代码，只检查有没有语法错误；
如果你改完 `extractor.py`，先跑这条命令，立刻知道有没有写错语法。
2. 项目打包、预生成字节码缓存。

## 6. 拓展小知识
如果你想一次性编译整个目录下所有py文件：
```powershell
python -m py_compile src\ontology_builder_agent\*.py
```

## 7. 补充区分
```bash
# 编译单个文件
python -m py_compile a.py

# 正常运行文件（解释执行）
python a.py
```
- `python a.py`：先编译字节码→立刻执行；
- `python -m py_compile a.py`：只编译、**不执行代码**，只输出pyc缓存文件。

> 对应你之前报错的 `extractor.py`，你可以执行这条命令快速检测：是不是代码里存在语法写错。
